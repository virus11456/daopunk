## 1. 專案概述

- **引擎**：Godot 4.3（相容 4.x）、GDScript（typed）。
- **類型**：2D 高角度俯視、半開放世界 RPG ＋ 生存 ＋ 派系 ＋ Tactical Pause 戰鬥 ＋ 系統化模擬。
- **設計方向**：
  - **美術**：參考 RimWorld 的高層次理念（俯視 tile、簡潔小型角色、資訊密度高），
    但**全部原創 placeholder**（圓形角色 ＋ 色塊建築 ＋ 程式生成地面），不使用任何 RimWorld 素材。
  - **玩法內容**：《Kiro：觀測者之夢》世界觀——五術（山醫命相卜）、十宇宙、功德、輪迴、世界變動率。
- **核心體驗**：玩家是世界的一部分，不是中心。NPC 有自己的生活、會死亡；用術招來觀察者；
  死亡＝輪迴，跨世保留修為（roguelite 循環）。
- **主場景**：`res://world/Main.tscn`。

## 3. 如何執行與測試

需要 **Godot 4.3+（Standard 版，非 .NET）**。

```bash
godot --path .                              # 開始遊戲（或用編輯器開 project.godot 按 F5）
godot --headless --editor --quit            # 匯入 ＋ 解析檢查（抓 parser error）
godot --headless --path . --quit-after 200  # headless 實跑（抓 runtime error，應無輸出）
godot --headless --path . tests/Smoke.tscn  # 整合冒煙測試（印 PASS/FAIL，離開碼＝失敗數）
```

**開發規約**：任何改動後跑上述三項，確認無 parser / runtime 錯誤、Smoke 全 PASS，再提交。

## 5. 架構總覽

三條設計原則貫穿全專案：

1. **Component 化，Player 與 NPC 共用**：能力/資料都放在可重用元件，掛在 `CharacterBody2D` 底下。
2. **資料驅動**：物品是 `.tres`（Resource）、對話與技能是 JSON；商店庫存、起始裝備、敵人配置皆以 id 引用。
3. **UI 解耦**：實體透過 `GameState` 的 signal 匯流排請求對話/商店，UI 只讀狀態，不驅動 gameplay。

### 5.1 Autoload 單例（`project.godot` 註冊）

| Autoload | 職責 | 關鍵 signal |
|----------|------|-------------|
| `GameState` | 全域參照（player、region）＋事件匯流排＋功德/世界變動率/世界旗標 | `dialogue_requested`、`dialogue_closed`、`shop_requested`、`karma_changed`、`world_variance_changed`、`world_flag_changed`、`player_registered` |
| `TimeManager` | 遊戲時鐘（日/時/分）、time_scale | `minute_passed` |
| `ItemDatabase` | 以 id 註冊所有 `.tres` 物品定義 | — |
| `Reincarnation` | 輪迴繼承（功德/五術/靈魂磨損）、世代 | `reincarnated`、`soul_wear_changed` |
| `ObserverSystem` | 世界變動率五階判定 ＋ 自然衰減 | `stage_changed` |

### 5.2 角色元件（Player 與 NPC 共用，`characters/components/`）

| 元件 | 職責 |
|------|------|
| `InteractableComponent`（Area2D） | 統一互動介面 `get_interactions(actor)` / `interact(actor, action)`；UI 不寫死動作 |
| `InventoryComponent` | 堆疊物品、容量、增減查詢 |
| `EquipmentComponent` | 武器槽，裝備/卸下與背包連動 |
| `FiveArtsComponent` | 五術熟練度與技能解鎖（讀 `data/skills/five_arts.json`） |
| `WalletComponent` | 金錢（Credits） |
| `HealthComponent` | 六部位健康、傷勢、流血、昏迷、死亡、五行屬性 |
| `CombatComponent` | 攻擊解算（武器 ＋ 五行相剋 ＋ 臂傷 ＋ 冷卻） |

Player＝`CharacterBody2D` ＋ 上述全部元件；NPC＝同一套元件 ＋ AI 狀態機。

### 5.3 事件流範例（按 E 跟 NPC 對話）

```
Player._try_interact()
  → 若焦點有多個動作 → InteractionMenu 選單
  → InteractableComponent.interact(player, "Talk")
    → Npc._on_interaction_requested → _start_talk
      → GameState.request_dialogue(名, 對話dict, 起點, npc)   ← 事件匯流排
        → DialoguePanel._on_dialogue_requested → 顯示、跑 conditions/effects
          → 關閉時 GameState.close_dialogue(npc)
            → Npc._on_dialogue_closed → 回到 Idle
```

## 6. 各系統詳解

### 6.1 五術（FiveArtsComponent）
- 五術：山（mountain）、醫（medical）、命（fate）、相（feng_shui）、卜（divination）。
- 每術有**熟練度**（使用成長），技能依 `proficiency_required` 門檻**解鎖**。
- 資料來自 `data/skills/five_arts.json`（每術 6 招，含等級/熟練需求/冷卻/功德消耗/效果）。
- 角色面板（`Tab`）顯示每術熟練度與已通技能（◆已通/◇未通）。
- 目前實作到「熟練度成長＋解鎖查詢」；招式的實際主動施放效果屬後續（K6+）。

### 6.2 功德與世界變動率（GameState ＋ ObserverSystem）
- **功德（karma）**：run 級資源，跨輪迴繼承 50%。算命、對話效果、功德珠可增加。
- **世界變動率（0–100）**：用改命類術/特定行為升高，招來觀察者；`ObserverSystem` 每秒自然衰減。
- 五階：安全區(0–30)/警戒區(30–50)/危險區(50–70)/紅色警報(70–90)/極限狀態(90–100)，HUD 以對應顏色顯示。
- 觀察者的**實體巡邏/天使機甲追殺**屬後續；目前提供偵測、階段與警示（戰鬥層已可反應）。

### 6.3 輪迴與靈魂磨損（Reincarnation）
- 繼承率：**功德 50%、五術熟練度 100%**、Credits/消耗品/聲望 0%，每輪**靈魂磨損 +1%**。
- 觸發：**玩家死亡自動輪迴**；或找**導師**（方舟隱修院＝輪迴起點）主動輪迴。
- 靈魂磨損階段：穩定(<30%)/頭痛幻覺(30–60%)/失憶人格變化(60–90%)/瀕臨崩潰(>90%)。
- **靈魂水晶**（消耗品）修復 10% 磨損。
- 實作上 `capture_and_advance()`（捕捉繼承、重置 run 資源）與 `reincarnate()`（多一步 reload 場景）分離，方便測試。

### 6.4 戰鬥（HealthComponent ＋ CombatComponent ＋ FiveElements）
- **健康**：六部位（頭/軀幹/雙臂/雙腿），各有 HP；傷勢帶流血率與疼痛。
  - 腿傷 → 降移速；臂傷 → 降攻擊命中/傷害；頭或軀幹歸零 → 死亡；失血歸零 → 死亡；疼痛/失血過高 → 昏迷。
- **攻擊解算**：命中＝武器命中率 × 臂部狀態；傷害＝武器傷害 × 五行相剋 × 臂部狀態 ×（1＋山術加成）。
- **五行相剋**：攻防雙方各有五行屬性，查 `FiveElements.TABLE[攻][防]` 倍率（見 §9）。
- **敵人 AI**（Npc `is_hostile`）：追擊 → 進入武器射程攻擊；血量 <30% 逃跑；死亡 → 屍體。
- 非戰鬥 NPC 受傷會逃；任何 NPC 死亡都留下**可搜刮屍體**（世界狀態保留）。
- 武器：小刀、木棒、左輪、霰彈槍、步槍（`WeaponData`，含傷害/射程/命中/攻速/裝填/噪音/類型）。

### 6.5 算命經濟（FortuneService）
- 對任何 NPC 選「算命」→ 替他卜卦 → 獲得 Credits ＋ 卜術/命術熟練度 ＋ 功德。
- 獎勵隨卜術熟練度與所帶工具（銅錢/量子骰子）提升；每個 NPC 有冷卻。
- 卦辭為本地模板（六則）；未來可接 Claude API 動態生成（設計文件的 fallback 機制）。

### 6.6 商店（ShopPanel）
- 找**紅·二師姐**對話選 `[交易]` 開店；買賣以物品 `base_value` 為基準。
- **議價**由**命術**熟練度決定：命術越高買越便宜、賣越貴；交易回饋命術熟練度。

### 6.7 對話（DialoguePanel）
- 資料驅動分支對話（JSON）。節點/選項支援 `conditions`（門檻）與 `effects`（改變狀態）。
- 見 §8 的完整 schema 與可用 condition/effect 型別。

### 6.8 物品與拾取
- `ItemData`（基底）/ `WeaponData` / `ConsumableData`，具體物品為 `.tres`，`ItemDatabase` 註冊。
- 地上 `ItemPickup` 提供「拾取」互動；敵人屍體提供「搜刮」（含裝備武器與財物）。

### 6.9 NPC AI 狀態機
- 狀態：`IDLE / WANDER / TALK / COMBAT / FLEE / DEAD`。
- 用 `NavigationAgent2D` 巡遊；只在閒置且計時器到期時才重新決策（不每 frame 決策，效能考量）。
- Schedule / Goal / Movement 分離的雛形；完整日程屬後續。

## 8. 資料格式參考

### 8.1 對話 JSON（`data/dialogue/*.json`）

```jsonc
{
  "start_id": "start",
  "nodes": {
    "start": {
      "text": "節點文字",
      "effects": [ /* 進入節點時執行（可省略） */ ],
      "choices": [
        {
          "text": "選項文字",
          "conditions": { /* 通過才顯示，可省略 */ },
          "effects": [ /* 選擇時執行，可省略 */ ],
          "next": "下一個節點 id"   // "end" 或缺省 = 關閉
        }
      ]
    }
  }
}
```

**可用 conditions**（皆可省略）：
| key | 意義 |
|-----|------|
| `require_flag` / `forbid_flag` | 需要/禁止某世界旗標 |
| `min_money` | 需要 ≥ 金錢 |
| `require_item` `{id, count}` | 需要背包物品 |
| `min_art` `{art, proficiency}` | 需要某術熟練度 |
| `min_karma` | 需要 ≥ 功德 |

**可用 effects**（`type` 決定）：
| type | 參數 | 作用 |
|------|------|------|
| `give_item` / `remove_item` | `id, count` | 給/收物品 |
| `add_money` | `amount` | 加金錢（可負） |
| `set_flag` | `flag, value` | 設世界旗標 |
| `add_proficiency` | `art, amount` | 加五術熟練度 |
| `add_karma` | `amount` | 加功德 |
| `add_world_variance` | `amount` | 加世界變動率 |
| `open_shop` | — | 開商店（來源 NPC 需 is_merchant） |
| `reincarnate` | — | 觸發輪迴（重載場景） |

### 8.2 五術資料（`data/skills/five_arts.json`）
```jsonc
{ "arts": [ {
  "id":"mountain", "name":"山術", "branches":["修命","修性"],
  "skills":[ { "id":"basic_breathing","name":"基礎吐納","level":"1",
    "proficiency_required":0,"cooldown":0,"karma_cost":0,"effect":"..." }, ... ]
} ] }
```

### 8.3 物品 `.tres`（Resource）
- `ItemData`：`id, display_name, description, kind(0 MISC/1 CONSUMABLE/2 WEAPON/3 TOOL), max_stack, base_value, icon_color`
- `WeaponData`（繼承）：`damage, attack_range, accuracy, attack_speed, reload_time, noise, weapon_class(0 近戰/1 手槍/2 霰彈/3 步槍), ammo_type`
- `ConsumableData`（繼承）：`heal, restore_stamina, art_proficiency{}, karma, soul_repair`

### 8.4 Main.tscn NPC 實例可覆寫欄位

is_hostile, aggro_range, flee_health_ratio, element(0金/1木/2水/3火/4土), starting_weapon`

## 10. 擴充指引（怎麼加東西）

**加一個 NPC**：在 `world/Main.tscn` 複製一個 `Npc` 實例，覆寫 `display_name / body_color /
dialogue_file`，需要對話就到 `data/dialogue/` 加 JSON。

**加一個物品**：在 `items/**/` 建 `.tres`（選對 Script：ItemData/WeaponData/ConsumableData），
到 `autoload/ItemDatabase.gd` 的 `_ready()` 加一行 `_register(preload(...))`。之後可用 id 放進
商店 `shop_stock`、對話 `give_item`、起始 `starting_loadout`。

**加一個敵人**：複製 `Npc` 實例，設 `is_hostile = true`、`element`、`starting_weapon`、`aggro_range`。

**加一個對話效果/條件**：在 `ui/dialogue/DialoguePanel.gd` 的 `_apply_effect` / `_passes_conditions`
增加分支即可（資料端在 JSON 用新的 type/key）。

**加一個世界地點/建築**：改 `world/Region.gd` 的 `BUILDINGS` 陣列（同一份資料同時餵視覺與導航挖洞）。

> 每加一個功能，請一併到 `tests/Smoke.gd` 增加對應檢查，並跑 §3 三項驗證。

## 12. 已知限制與後續路線

**目前限制（刻意，屬後續）**
- 五術招式尚未有主動施放的完整效果（目前是熟練度成長＋解鎖）。
- 只有一個宇宙（歸墟），尚無跨宇宙切換。
- 觀察者只做到「偵測＋警示」，尚無實體巡邏/天使機甲追殺。
- 尚無存檔系統（輪迴在單場 session 內運作；跨啟動存檔屬 K6/K 後）。
- 尚無感情/記憶繼承、組織、房產、法則碎片、結局。
- 全為 placeholder 美術。

**建議下一步**：K6 多宇宙（宇宙切換 ＋ 太虛星圖）、或先補**存檔系統**（讓輪迴跨啟動保留、
並解鎖鐵人模式＝死亡刪檔的硬核 roguelike）。
