# 隨機事件資料與離線參考模型

本批為提案。4 個無名測試模板、22 項離線行為檢查，不是 300 則正式事件，不含劇情台詞、Godot、戰鬥或獎勵數值。依據主線 v2、遊戲量規劃 v2 與 NPC 生活資料契約。

沿用已定：世界持續前進，正式輪迴不倒轉世界；惡化不因玩家晚幾輪就自動觸發終局。第一輪十五歲下山。此模型的 tick 僅為抽象時間，不決定遊戲日長、年長或出生等待。

## 三種重複性

| 類型 | 規則 | 樣本 |
|---|---|---|
| once | 同一模板在此世界結算一次，缺席結算也消耗其一次機會 | 臨時通道勘查 |
| periodic | 結算後等冷卻，資格仍成立才可建立新實例 | 遮雨棚修補、風土觀測輪值 |
| consequence | 必須先有歷史效果，本樣本每條後果鏈只結算一次 | 缺料後替代棚架 |

正式內容若要每個聚落各發生一次，必須引入地點作用域鍵；不能直接把此模型的全世界一次限制冒充多地點版本。後果型若需要再次發生，應建立有明確原因的新鏈實例，不能清除歷史讓舊鏈重演。

## 資料欄位

模板有 id、kind、title_proposal、location_tags、participant_tags、requires_flags、forbids_flags、mutex、cooldown、window，以及 present / absent 兩組 outcomes。每個結果含 id、weight、add_flags、remove_flags、permanently_resolve。

實例有獨立 id、event_id、created_at、deadline、context、definition 快照、status、completed_at、mode、outcome。狀態保存世界 tick、seed、flags、resolved 永久解決集合、last_completed、occurrences 及 history。

權重只演示可重現結算，不是算命成功率或正式事件平衡。作者版完整结果資料也不能直接傳給 NPC 對話生成；只依後續消息契約發送角色能得知的內容。

## 執行順序

1. 檢查地點與參與者標籤、必要／禁止歷史條件。
2. 排除永久解決、一次性已結算、冷卻中及已有同模板待決實例；互斥組同時最多一件待決事件。
3. 由呼叫方選擇合格模板，建立持久化實例。此版未實作整池抽選或權重平衡。
4. 保存模板快照；在玩家在場或到期缺席時結算，保存實際結果與效果一次。
5. 相同實例 ID 的再次開始／結算返回已保存結果，不再增添歷史、不再次套用效果；不同事件冒用同 ID 直接拒絕。

永久解決遮雨棚修補後，不會因冷卻結束再抽回舊問題。修補未完成而留下缺料，才有後果事件資格。互斥只限制待決期間，並非所有後續歷史永遠互斥。

## 缺席、存檔與輪迴

advance 依 deadline、實例 ID 的固定順序結算已建立但玩家缺席的事件，截止點當下即算缺席；大步跳過與逐 tick 結算結果一致。未建立的模板不會自行產生事件：世界排程器將來仍需負責建立到期世界事件，不能將此模型描述成完整的離線世界模擬。

實例及其歷史屬世界資料，輪迴時應保留。此版沒有輪迴函式，也不清除當世修為等其他系統欄位。JSON 存讀保持待決抽選與既成結果；任意改 seed、篡改存檔、舊存檔回溯和版本遷移未處理，不代表讀檔政策已定。

多結果用 seed、實例 ID 與在場／缺席模式的 SHA-256 決定，避免進出地圖重抽。正式實作應讓實例 ID 由世界排程穩定產生，不能讓呼叫端反覆換 ID 挑結果。

## 驗證

```sh
python3 tools/check_random_event_contract.py --report docs/contracts/random-event-validation.json
```

22 項檢查涵蓋參與者／地點資格、後果前提、互斥、一次性消耗、冷卻邊界、缺席、永久解決、時間不可倒轉、實例 ID 衝突、歷史去重、存讀結果與效果一致、待決模板快照、補算等價及重複模板 ID 拒絕。

限制：未做資源原子扣除、人物死亡替代、AI 對話、新聞傳播、分區公平抽樣、跨宇宙排程、Godot 存檔、完整資料型別驗證或效能測試。4 個樣本只是機制案例，未計入正式劇情事件交付量。
