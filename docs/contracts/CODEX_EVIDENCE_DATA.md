# 山海圖鑑證據資料格式｜離線提案 v0.1

依據：`docs/story-drafts/shanhai-codex-v1.1/README.md` 與 `docs/story-drafts/main-v2/README.md`。本文件及 Python 參考模型是資料行為提案，未接 Godot、AI、存檔或介面；沒有製作百條正式經文，也沒有圖像。樣例全部為合成測試，沒有冒充古籍引文。

## 已定規則如何保存

主角記得親歷，不等於知道作者設定。開局背過的經文由「實際讀過」紀錄填入，可呈現上百個未親見條目；未讀過的批註、殘圖、別人的夢，不因存在於資料庫就可見。正式輪迴保持記憶、世界時間向前；世次是紀錄座標，不是親見事件的固定解鎖條件。

不收一般個別人物。族群／型號、山川、遺跡可為條目；人物只作消息來源或觀察中被提及。古籍記載的神與道主是否可作「古籍對象」而非人物傳記，仍為編輯提案。本模型要求此類標記 proposal，不替使用者定案；不生成好感、任務或傳記欄。

## 三層資料

| 層 | 用途 | 玩家可見規則 |
|---|---|---|
| 作者目錄 | 穩定條目 ID、類型、待編輯秘密 | 不直接序列化給玩家 |
| 已取得證據 | 讀經、轉述、親見、未見、訂正、批註 | 事件已實際發生、時間已到且條件滿足才追加 |
| 玩家投影 | 條目公開標籤、已取得紀錄、並存狀態 | 沒有任何取得紀錄就不顯示此條目 |

公開標籤本身也不能含未揭露身份，例如未經證實前不可把「帝江」標成「帝江／渾沌」。本原型的 public_label 須由編輯保證無劇透，名稱解鎖／別名層級尚未實作。作者秘密測試欄故意放入樣例，確認輸出不攜出它。

## 一筆證據

| 欄位 | 意義 |
|---|---|
| id | 世界中這次取得事件的唯一 ID；重送不重複，改內容須新 ID |
| entry_id | 被描述對象，不是說話者 ID |
| kind | text／rumor／observation／revisit_absent／correction／annotation |
| source_id | 這次直接接觸的書本、說話者或觀察事件 |
| root_source_id | 可追溯的原始消息鏈；兩人口傳同一新聞沿用同根 |
| life | 取得紀錄時的主角世次 |
| world_time | 所述事情／來源所指的世界時間 |
| acquired_at | 主角取得紀錄的世界時間，不可早於 world_time |
| place | 取得／觀察地點；歷史地點另在內容明示 |
| text | 此時可知的描述，禁止混入條件尚未達成的秘密 |
| requires | 由事件系統確認的知識條件，不自行推出 |
| citations | 訂正所用已取得證據 ID，同條目且必須存在 |

時間樣例使用單調遞增的測試刻度，並非正式遊戲年曆。實際不明日期、古籍年代區間、轉述所述地點等，需要後續加入不確定性欄位；目前不能把猜測的年月當確切時間輸入。

`occurred` 與 `known` 由可信世界／劇情事件來源提供，不是讓生成式 NPC 自行填寫。這個原型檢查取得門檻與輸出邊界，不能辨識文句語意是否含劇透，仍須編輯檢查。

## 狀態不能是一條升級線

- 未親見與聽聞可共存；可直接親見，不要求先聽聞。
- 親見只代表當時當地，跨世再見要有不同世次的親見。
- 再訪未見只記這次沒有看見，不推導遷徙或全球滅絕，也不刪掉舊的親見。
- 訂正追加主角的判斷、引用依據；既有經文与親見永不覆寫。引用存在只是可追溯，不是自動認證結論為真。
- 來源矛盾並列，後來的更正可以再追加；不以最新文字覆蓋歷史。
- 同一事件去重，兩次真正重訪有不同事件 ID；重播舊事件不能當新親見。
- 同根轉述留兩份聲音，但來源鏈只計一次。`source_lineage_count` 是追溯根數，不是獨立證據數或真實機率；訂正依賴引用，不能拿它再次增加結論可信度。

## 跨世與物件

`reincarnate` 複製已取得記憶並使時間向前，新身體背包為空。書、古圖、木雕的保管位置留在世界物件登錄，沒有傳送。經文記憶或素描記憶不等於仍持有原件，也不保證第三者接受主角的記憶作實證。世界模擬可在經過的時間中另行更改保管者、損壞或拆除；本函式不模擬這些變化。
