# 跨篇故事資料契約｜引擎接入前提案

本文件只規劃資料邊界，與[輪迴契約](REINCARNATION_DATA.md)並用。沒有實作Godot讀取器、對話引擎或正式存檔；不固定出生、戰鬥、好感數值或分支結果。

## 必須分開的狀態

| 類別 | 建議欄位 | 邊界 |
|---|---|---|
| 世界事件 | event_id、occurred_at、location_id、participants、outcome | 事件可以在玩家缺席時發生；未知日期用null與待定理由，不用0假裝已定 |
| 傳播消息 | report_id、event_id、source、published_at、arrived_at、claims | 真相、官方聲明、口述與更正不是同一資料；發生不等於主角已聽說 |
| 角色所知 | subject_id、claim_id、learned_at、source_id、confidence、scope | 主角、NPC與觀眾知道的事各自保存；完整記憶不生成未知內容 |
| NPC記憶 | npc_id、life_id、recall_state、unlocked_fragments | 局部／足以相認與資料查閱分開；玩家輪迴不重置NPC或替它解鎖 |
| 關係 | recognises_player、trust_state、willingness、current_goal | 認出不等於信任、合作或服從；數值加減不是本版正式規則 |
| 同意 | subject_id、purpose、data_scope、granted_at、revoked_at | 同意讀命、查檔、訪談、研究、公開分開；邀請前往不代表全權授權 |
| 請求與承諾 | request_id、status、deadline、responsible_actor、resolution_event | requested／accepted／delivered／fulfilled／declined／expired不同；信寄出不等於送達 |
| 實體物件 | item_id、custodian、location、ownership_claims、history | 持有、保管、借閱、所有權不同；世界物件不跟玩家輪迴自動搬家 |
| 場景進度 | scene_id、visited、selected_choices、resolved_outcomes | 看過場景不等於看過其中每個選項；scene_complete不能代替具體知識 |

上述英文值是待採用的工程命名，不能用來反推正史。

## 具體跨篇讀取需求

| 來源→讀取處 | 必須保存 | 缺少時的處理要求 |
| S01→D01／S02／M01 | 古舊算命紙與新空白紙各自的持有鏈 | 不能合併為同一件；未交接就不可出現在另一人櫃中 |
| R01→S02 | 修燈共同經歷、入櫃或旁觀、是否偷看 | 只核對真正在場的內容；未見船不得稱早已知道船 |
| Z01→X01／D01 | 零號身體方案、過渡到期、接頭是否仍需要 | 不強制所有方案回到取同一件零件；期限到由世界處理 |
| X01→D01 | 阿錨請藥是否送達、灰隼是否承諾／到場、星塵現況 | 多項介入的交集需唯一結果，不能由結果表順序偶然決定 |
| D01→S02 | 實際疏散、誰受託、傷亡資料及其來源 | 沒有委託杜七就不可回憶主角請酒；無資料的傷亡保持未知 |
| S02→M01 | 是否寄信、紅轉交授權、信件送達、拾六是否相認 | 未寄信需獨立聯絡來源，不寫收到回信；不洩露他人保密地址 |
| M01→後續 | 研究對象同意範圍、資料副本／保管者、稽核通知日 | 不以研究方式代替命錨測試已暫緩；期限從通知事件起算 |
| F01→Y01 | 葉遲實際記憶狀態、小芽申請／出發承諾、到期日 | 沒唱歌不能一律稱主角喚醒；一年後須有進展或失約消息 |
| Y01→後續 | 兩份紀錄已知範圍、封存欄位、研究同意、問棋託付 | 未問雙重申請先補告知；不能抹除報紙、副本或主角記憶 |

## 分支與時間的驗收要求

- 同一可達狀態若命中多個結果，須明定互斥條件或優先序；沒有命中也須有缺席／未達條件路徑。
- 問話可以是可重複調查，離開或承諾則可能是狀態改變，需逐項標明；不假設所有選項單選。
- 世界發生時間、消息送達時間、玩家觀看時間分開；兩地行程不能因場景完成瞬移。未定交通速度保持待定。
- 觀測機率要附條件、觀測時點、結果範圍與未知餘量。不同介入條件的機率不直接合計；結果表不能默默把概率改成必然。
- 故事效果用event_id去重；重訪不再發一次實體信或法則。改變主意應新增後續事件而非刪去歷史。
- 讀檔保留尚未完成的承諾與原期限；玩家輪迴保留世界事件、主角已知及永久能力，當世醫術依輪迴契約清除。
