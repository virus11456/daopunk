# 房產、NPC 來訪與跨輪迴舊居

狀態：使用者於 2026-09-26 要求納入的系統設計；**尚未實作**。現有 README 將組織／房產列在 K6+ 後續內容，現行遊戲沒有買房、NPC 入住或跨啟動存檔功能。

## 肉鴿定位

依[肉鴿核心循環](ROGUELITE_LOOP.md)，房屋是當輪可選投資與跨世敘事錨點。未買房也可通關；售價與服務收益以一輪尺度平衡。來訪以路線進度／事件節點觸發，不依現實時間等候。住宅休息及整備需消耗有限服務次數或節點行動機會，不可反覆刷取收益。

## 核心循環

探索城市 → 查閱房屋與條件 → 購買本世產權 → 整備／收藏／邀請 NPC → 建立記憶錨點 → 輪迴 → 重訪地址 → 找回痕跡與人物記憶 → 決定重新購屋、協商進入或另立新家。

每個宇宙可以有多顆星球，每顆星球可以有多座城市，每座城市可以有多個 property_id。40 張地點圖只是一批內容，不是世界容量上限。

## 本世房產

- 房型：小居（休息與基本倉儲）、工坊宅（製作／五術整備）、庭院宅（來訪與記憶事件）。這是功能分級，不是固定價格承諾。
- 購屋前顯示城市、地址、可用功能、產權限制、一次性價格與是否有持續費用。本原型不設強制離線租稅。
- 買賣只處理 Credits；功德不是房價代幣。價格、容量與收購折扣需依現有經濟試算後設定。
- 選擇確認購買後，扣款、產權登記、交易紀錄必須同一筆原子存檔；不足款不扣錢。重讀存檔不得重複扣款。
- 普通倉庫只在本世保存；罕見紀念品需放入封存槽才參與輪迴繼承。
- 休息不免費重置商店、獎勵、一次性事件或法則施放次數。戰鬥、追捕及危險狀態的休息限制需要 UI 預告。
- 主角有產權不代表能任意控制住客；NPC 可拒絕、離開或因事件無法到訪。

## NPC 拜訪與入住

拜訪條件＝認識角色＋關係／信任條件＋前置事件完成＋當前角色存活且可行動＋房屋適合＋收到邀請＋行程允許。入住另需明確同意和空餘房間。

| 角色 | 可用事件方向（新增提案） | 限制 |
|---|---|---|
| 導師 | 傳授五術、解讀輪迴痕跡 | 導師保留方舟隱修院職責，不默認永久同住 |
| 紅・二師姐 | 同門聚餐、寄存舊物、短暫補給 | 不因此免費取得整間商店庫存；不是戀愛預設 |
| 星塵 | 安全會面、革命聯絡、戰後休息 | 不因買房自動加入派系；追捕期間會面可能延期 |
| 零號 | 探問機械靈魂、修復記憶物件 | 不把記憶喚醒直接等同感情或服從 |
| 其他同門 | 待具名後接入邀請規則 | 未知姓名、排行及設定不得當成既有 NPC |

房屋面板顯示「已邀請／預計來訪／暫時無法／已入住」，無法到訪給出不劇透的原因。排程要能避開正在對話、戰鬥與主線任務的 NPC。死亡或跨城離開會取消／改期，不生成分身。

## 輪迴重置與保留

| 資料 | 輪迴規則 |
|---|---|
| 本世產權、買賣款項、普通倉庫、房客排程 | 重置；不保證下世仍持有房子 |
| 曾居住地址、發生過的重要記憶 | 以世界線穩定 ID 保留為記憶索引 |
| 家具與房屋外觀 | 可能留下痕跡，但不當成保證繼承的財產 |
| 封存紀念品 | 原型每個存檔的輪迴檔案只開 1 個跨世槽；全體房屋共用，不可靠買多屋增加 |
| NPC 的前世記憶 | 個別 memory_echo 記錄；知道玩家曾來過，不等於恢復全部關係 |
| 現世買家與房屋狀態 | 下一世依敘事狀態生成，可能易主、損毀、改建或封閉 |

封存需在輪迴前完成，消耗與物件移轉一次提交。提取後把唯一 item_instance_id 從封存槽移出並寫入 claim_receipt；同一紀念品不能同時在倉庫、背包與封存中。禁止攜帶整批武器或金錢穿越輪迴；封存物品以 approved_keepsake 白名單限制，僅用於故事線索與對話選項，不繼承前輪戰鬥數值、卡牌升級或裝備效果。

## 記憶錨點與重返事件

記憶錨點必須由玩家與人物／地點的實際事件建立，不是只買屋便自動永久加成。載體可為牆上刻痕、門檻、種下的樹、藏在暗格中的物品。

- **房屋易主**：先協商、交換幫助或重新購買。不能因前世產權直接拿走現任屋主財物。
- **房屋損毀**：記憶錨點轉到原址殘跡，仍提供故事線索；不憑空復原整屋。
- **地址未生成／路線不可達**：記憶記錄保留，設對應遺址或延期事件；不讓主線必需品永久卡死。
- **多個錨點指向同一 NPC**：依 event_id 和靈魂 ID 去重，只觸發一次對應階段。
- **出售房屋**：失去本世使用權；留下的記憶仍存在，私人倉庫物品需結算轉移，不默默消失。
- **死亡時正在交易或搬家**：先取消未提交交易，再做輪迴捕捉；不可半扣款、半登記。

### 範例：紅的煙斗（新增支線提案）

第一世：玩家購屋，完成同門互助事件並邀請紅來訪。她寄放一只舊煙斗；只有明確交付給玩家的版本才可封存。

第二世：主角回到舊居，在原址暗格找到事件痕跡或依法取回封存紀念品。把煙斗帶給紅可觸發熟悉感／同門記憶，**不保證她立刻記得全部前世，也不強制提高親密關係**。

同一事件有 once_per_soul_stage 限制；來回放置煙斗不能刷功德、金錢或熟練度。

## 資料模型與儲存責任（後續實作提案）

- PropertyDefinition：property_id、universe_id、planet_id、city_id、lot_id、house_type、功能、購買條件。
- RunPropertyState：run_id、owner_id、倉庫、家具、房客、排程、交易收據。
- MemoryAnchor：anchor_id、stable_location_id、soul_id、事件階段、上一世索引、顯示痕跡。
- ReincarnationProfile：已知舊址、全域封存槽、唯一紀念品、已領取收據、NPC memory_echo。
- 前置工作是具版本號的存檔、原子寫入、載入遷移與失敗回滾。現有 Reincarnation 的 session 記憶不能冒充持久存檔。
- 行為由小型房產／拜訪／錨點服務分工，以 signal 通知 UI；不往 GameState 塞整套巨型系統。
- 保存來源與 card_design 一樣，置於設計資料；本次不註冊尚未存在的 Godot Resource。

## 城市與美術標記

每張新配置圖預留一個候選住宅入口及可連通道路，以米色小旗／鑰匙形門牌作提案標記；圖上的標記不是已實作購屋按鈕。墓園、工業區、深淵等地使用適合環境的宿舍、守門人小屋或避難居所，保留地點性質。

後續室內分件：床、桌椅、儲物箱、來訪座位、封存暗格、紀念品台、庭院錨點。現階段城市圖只呈現外觀位置，不表示每棟房屋都完成室內或可購買。

## 驗收案例（實作時執行）

足額購買一次／重開遊戲不重扣；不足款不變更；NPC 拒絕與死亡不產生分身；讀檔後排程一致；輪迴後普通產權重置；封存只能領一次；連買多屋不增加全域封存槽；售屋後倉庫結算；地址損毀可找到遺址；記憶事件不可刷獎勵。

此文件是已接受的設計方向，仍需原型與測試，不是完成系統的宣稱。
