# 同一城市、每輪不同布局：區塊生成

使用者提出並採用的設計方向：城市保留身分與特色，每輪由不同區塊組合成新布局。現有完整城市概念圖是配置範例與拆件參考，不是必須整張固定使用的背景，也不是已可直接切割的圖集。

## 固定與隨機

固定：city_id、所屬星球、城市主題、核心地標種類、必要服務、敘事地址 ID。隨機：區塊變體、相對位置、允許的道路連接、支線、小型裝飾、可選店舖。世界事件可調整抽選權重，例如戰後增加修復區塊、封鎖增加檢查站。

每座城市先規劃入口、主地標、市場／補給、住宅、工作、出口六種功能角色，依城型使用不同名稱；陵墓使用交接亭／管理宿舍，深淵使用避難點，不把所有地方改成一般市場城市。每類先做 2～3 個原型變體再擴充，不承諾本批已畫完所有區塊。

## 組合規則（原型提案）

區塊暫以 16×16 地磚為基本單位，大地標可佔多格；地磚像素尺寸依最終製作規格統一。每個區塊資料記錄尺寸、方向、入口 socket、可走網格、功能標籤、建物錨點、地形／高度與禁用組合。俯視素材不可隨意旋轉，僅使用已繪製的方向變體；文字與非對稱地標不靠鏡像充數。

流程：用 city_id＋run_seed 決定城市子種子 → 先建必要功能的連通圖 → 放入口、主地標及出口 → 配置住宅與工作區 → 填可選街區 → 接道路 → 驗證 → 保存完整布局及生成器版本。對話、戰鬥亂數與城市生成器分離，聊天不改變地圖。

必要條件：所有任務入口、基本補給與出口可達；所有 NPC 的住處與工作點有可走路徑；多格建物不重疊；水面／裂隙與高低差需合法橋梯；安全住宅不落在危險地形。失敗時有限次重試，之後使用該城市已驗證的備用配置，不能無限生成或卡住讀取。

當輪生成後固定，讀檔、進出房間、走到另一星球再返回都不改版；只有輪迴或明示的劇情重構事件能改布局。保存布局結果以避免程式升級後同種子產生不同地圖。

## 舊宅與人物連續性

property_id／stable_address_id 綁城市和敘事宅地，不綁像素座標。新一輪先將記憶宅地配置到適合的住宅區塊，再設定當世座標及擁有者。門牌、樹木、刻痕或暗格可作辨識線索；任務路標指向本世地址，不能沿用前世座標。

主線必要錨點先預留；可選舊宅若因劇情損毀，使用遺址區塊；若本輪城市不在路線上，延期保留事件，不讓主線必需物品被隨機吞掉。多個前世房屋競爭空間時按敘事優先度及容量規則選擇，未配置者保留在紀錄，不靜默刪除。

NPC 綁職業／家庭與功能錨點，由新布局計算作息地點和路徑；不能只將舊座標貼到新房屋。星主稱號、政治歷史與城市 ID 不因布局改變而換成另一座城市。

## 美術交付與 Godot 分工

本批 40 張完整配置圖每張示範一個可能布局；後續拆成道路、地面、建物與功能區塊。像素 PNG／圖集可直接進 Godot；Blender 用於重用建築或多角度地標底稿，再整理成一致像素。不能宣稱概念圖已自動完成地磚、碰撞、導航或程序生成。

先用破爛街做一個可玩垂直切片：六種功能區塊各兩變體，測試不同種子連通、舊宅跨世重新落點、NPC 上下班與卡牌戰鬥返回位置。實作需測多種子覆蓋、生成耗時上限、同輪載入一致與舊存檔遷移。
